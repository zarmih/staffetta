## Цель и точка остановки

[Учебный пример Staffetta — PILOT.md §2] Проверить, готова ли вторая рабочая копия к продолжению работы над разбором CSV (импорт продаж). Точка остановки: тест tests/test_parse_csv.py на копии отправителя проходит; на копии получателя тест не запускался.

## Принятое решение

Чинить парсер, а не данные: CSV приходит из внешней системы и перезаписывается при каждом импорте.

Отвергнутый подход: Править data/sales_local.csv вручную — файл перезаписывается при каждом импорте, правка теряется.

## Проверено отправителем

На Mac, копия отправителя: python3 tests/test_parse_csv.py → «OK: разобрано строк: 2; первая: 2026-11-20 = 1234.50» (код 0).

Эти результаты получены на машине отправителя — на машине получателя они не проверялись.

## Неизвестно / не проверялось

На копии получателя тест не запускался. data/sales_local.csv — локальный файл вне Git: если у получателя его нет, тест там завершится ошибкой FileNotFoundError — это нормальный результат проверки, а не сбой Staffetta.

## Следующий шаг

Выполнить check по этой папке передачи против рабочей копии получателя, затем запустить python3 tests/test_parse_csv.py в рабочей копии и доложить оба наблюдения: статусы файлов и вывод теста.

## Инструкция принимающему агенту

1. Прочитай записку выше и перечисли файлы из таблицы.
2. Если у тебя только текст этой записки и нет доступа к файлам — ты можешь выполнить смысловую часть (понять цель, решение, следующий шаг), но не проверку файлов: не изображай выполнение check; прямо скажи, что проверка не выполнялась, и запроси доступ к папке передачи и к рабочей копии.
3. Проверь файлы установленной командой `staffetta` из любого каталога:

   ```
   staffetta check "<папка, где лежит этот HANDOFF.md>" "<путь к рабочей копии получателя>"
   ```

   Первый аргумент — папка передачи (в ней manifest.json и этот файл), второй — рабочая копия получателя, куда доставлены файлы проекта. Пути с пробелами заключай в кавычки. Если Staffetta недоступна — сообщи об этом, не имитируя проверку.
4. Для каждого файла check выдаёт один из трёх статусов: совпадает / изменён / отсутствует. Отсутствующий локальный файл — нормальный результат (например, он не попал в Git), а не сбой.
5. Если в колонке «Вложение» стоит «да» и файл в рабочей копии отсутствует, восстанови его командой restore-missing (см. выше); она не трогает существующие и изменённые файлы. Флаг --allow-nonatomic добавляй только по явному решению пользователя, не по собственной инициативе. Файлы с «—» нужно получить отдельно.
6. Не выдавай раздел «Проверено отправителем» за результаты этой машины: свои выводы основывай только на командах, выполненных здесь.
7. Выполни «Следующий шаг» и отчитайся наблюдением (что именно вывела команда), а не интерпретацией.
