# PILOT.md — ручной эксперимент «Эстафета»

Проверяем, сокращает ли короткая записка время до первого полезного действия при смене агента, чата, IDE или компьютера. В эксперимент входят Codex, agy, Grok, Hermes, OpenCode, ZCode и GitHub Copilot в VS Code. Для нового инструмента достаточно способа передать текст. Записку можно прочитать из проекта, вставить в чат или передать вместе с выбранным вложением.

## 1. Шаблон записки (заполнение ≤ 1 минуты)

Пять строк. Указывай только известные факты.

- **Цель/точка:** <что нужно получить> · <где остановился>
- **Решение:** <принятое решение и почему> · **Отвергнуто:** <подход и причина>
- **Материалы:** <пути от корня проекта, вложения или выдержки> · <что передано и что осталось только у отправителя>
- **Проверено:** <кем, где, на каких данных и с каким результатом> · **Неизвестно:** <что ещё требует проверки>
- **Первый шаг:** <одно действие> · **Признак:** <наблюдаемый результат «можно двигаться дальше»>

## 2. Учебный пример заполнения

⚠️ УЧЕБНЫЙ ПРИМЕР — задача и результаты вымышленные, использованы только для демонстрации формы.

- **Цель/точка:** починить разбор CSV в импорте продаж · ошибка воспроизведена на Mac, причина предположительно в десятичной запятой, исправление не начато
- **Решение:** чинить парсер, а не данные — CSV приходит из внешней системы · **Отвергнуто:** правка CSV вручную — файл перезаписывается при каждом импорте
- **Материалы:** в проекте — `src/import/parse_csv.py` и `tests/test_parse_csv.py`. Файл `data/sales_local.csv` остался на Mac, в Git его нет.
- **Проверено:** на Mac выполнен `pytest tests/test_parse_csv.py -k comma` → падает с `ValueError: could not convert '1 234,50'` · **Неизвестно:** поведение на Windows не проверялось
- **Первый шаг:** проверить доступность исходного CSV для повтора теста · **Признак:** файл найден и тест можно запустить, либо точно указано, какой материал нужно передать. Результат на синтетическом примере записывается отдельно.

## 3. Что делает принимающая сессия

Посмотри, что доступно в этой сессии. Файлы, вложения и запуск команд могут быть доступны по отдельности.

- Если видишь рабочую копию, проверь нужные пути. Если доступен запуск и есть исходные данные, выполни проверку и запиши результат вместе со средой.
- Если видишь только текст или вложение, выполни доступную часть задачи. Например, по значению `1 234,50` предложи отдельные проверки пробела и десятичной запятой. Если нужен исходный файл, укажи какой. Отсутствие доступа к каталогу означает «наличие неизвестно».
- Передавая задачу дальше, дополни записку результатом своего шага и следующим действием. Сохрани источник предыдущих наблюдений. Так вывод из чата можно вернуть исполнителю для проверки.

## 4. Сравнение с обычным способом перехода

Выбери один переход из текущей работы. Примеры:

| Что меняется | Возможный маршрут | Что проверить |
|---|---|---|
| Агент, рабочая копия та же | Codex → agy или OpenCode → Copilot в VS Code | Получатель продолжает с точки остановки и учитывает причину прежнего решения. |
| Доступ к материалам | Hermes → Grok в режиме чата → Hermes | Чат разбирает переданный фрагмент. Исполнитель получает конкретную проверяемую гипотезу и проверяет её на файле. |
| Компьютер и агент | Codex на Mac → ZCode на Windows | Получатель обнаруживает, какие материалы доступны на втором компьютере, и указывает источник каждого результата. |

Заранее запиши, что будет первым полезным действием в выбранном маршруте. Проведи два прогона из одной исходной точки в свежих сессиях одного получателя с одинаковым доступом. В одном передай задачу привычным способом, в другом используй шаблон. Для каждого запиши время от начала подготовки до полезного действия, число дополнительных пояснений и что пришлось перенести вручную. Для чата полезным действием может быть разбор вложения. Для исполнителя — запуск проверки или точное обнаружение недостающего файла.

## 5. Критерии

- **Хватит шаблона**, если получатель сделал полезный шаг без дополнительных пояснений, а подготовка и передача материалов заняли приемлемое для тебя время.
- **Стоит автоматизировать конкретный шаг**, если на следующей реальной передаче повторяется та же ручная работа. Зафиксируй её и затраченное время. Копирование выдержек в чат и поиск отсутствующего файла на другом ПК требуют разных решений.

Оба критерия сформулированы до эксперимента из §4 и могут уточняться по его результату.
