# Staffetta

Staffetta помогает продолжить задачу в другом ИИ-агенте. Она собирает записку с принятыми решениями, следующим шагом и выбранными файлами. Агент с доступом к рабочей копии может сверить файлы по SHA-256, а в обычный чат можно вставить вопрос с нужными строками кода.

Проверено на macOS. Проверка на Windows пока не проводилась.

## Установка (один раз)

Для установки на macOS требуется Python ≥ 3.10. При первом запуске из GitHub скачайте исходники и готовый wheel:

```bash
git clone https://github.com/zarmih/staffetta.git
cd staffetta
mkdir -p dist
curl -fL https://github.com/zarmih/staffetta/releases/download/v0.3.3/staffetta-0.3.3-py3-none-any.whl -o dist/staffetta-0.3.3-py3-none-any.whl
```

Выполните следующий блок из корня проекта. По файлам в `dist/` pip выбирает последнюю
совместимую локальную версию, а повторный запуск с `--upgrade` обновляет
ранее установленную. Установка — в отдельное окружение, глобальное окружение
не меняется:

```bash
staffetta_install() {
  STAFFETTA="$(pwd -P)"
  python3 -m venv "$HOME/.venvs/staffetta" || return 1
  "$HOME/.venvs/staffetta/bin/python" -m pip install --no-index --find-links "$STAFFETTA/dist" --upgrade staffetta || return 1
  mkdir -p "$HOME/.local/staffetta-bin"
  TARGET="$HOME/.venvs/staffetta/bin/staffetta"
  LINK="$HOME/.local/staffetta-bin/staffetta"
  if [ -e "$LINK" ] || [ -L "$LINK" ]; then
    if [ "$(readlink "$LINK" 2>/dev/null)" = "$TARGET" ]; then
      echo "Ссылка уже указывает на установленную Staffetta: $LINK"
    else
      echo "Путь занят другим объектом: $LINK → $(readlink "$LINK" 2>/dev/null || echo 'обычный файл или каталог') — сохранён, PATH не изменён."
      return 1
    fi
  else
    ln -s "$TARGET" "$LINK" || return 1
    echo "Ссылка создана: $LINK → $TARGET"
  fi
  case ":$PATH:" in
    *":$HOME/.local/staffetta-bin:"*) ;;
    *) export PATH="$PATH:$HOME/.local/staffetta-bin" ;;
  esac
}
staffetta_install
```

Три исхода шага ссылки: путь свободен — создаётся обычная ссылка `ln -s` и
каталог добавляется в `PATH` только при успехе; ссылка уже указывает на
установленную Staffetta — остаётся как есть, а каталог появляется в `PATH`
не более одного раза; путь занят чем-то другим (обычный файл, каталог,
ссылка на другую программу, оборванная ссылка) — объект сохраняется, его
путь показывается, шаг завершается с ненулевым статусом и `PATH` остаётся
прежним. Блок вставляется в интерактивную оболочку без закрытия терминала:
выход из конфликтной ветки выполняется через `return` внутри функции.

Каталог ссылок содержит только `staffetta`; `python3` и `pip` ваших других
проектов остаются прежними. Для постоянного доступа добавьте в `~/.zshrc`
строку `export PATH="$PATH:$HOME/.local/staffetta-bin"`.

Если `staffetta` уже доступна из другого места, проверьте, какой экземпляр
запустится (первый в `PATH`) и какие есть вообще:

```bash
command -v staffetta && type -a staffetta
```

Кто что делает с данными: `check` и `brief` — только читают; `pack` — создаёт
новую папку передачи; `restore-missing` — единственная команда, которая может
записывать файлы получателя (только отсутствующие вложенные, по умолчанию
атомарно; существующие и изменённые не трогает). Ничего не отправляется по сети.

Пересборка wheel после изменения кода — и из копии на APFS, и с `--outdir` на
APFS: на томе exFAT сборка даёт пустой пакет, а запись wheel в `dist/.tmp-*`
тома ломается посреди записи. При первой сборке pip забирает setuptools в
изолированную сборочную среду, то есть нужен доступ к сети:

```bash
BUILD="$(mktemp -d)"
rsync -a --exclude '.git/' --exclude '._*' --exclude '__pycache__' --exclude demo --exclude tests --exclude dist --exclude build --exclude staffetta.egg-info "$STAFFETTA/" "$BUILD/src/"
python3 -m venv "$BUILD/venv"
"$BUILD/venv/bin/pip" install --quiet build
"$BUILD/venv/bin/python" -m build --wheel --outdir "$BUILD/dist" "$BUILD/src"
cp "$BUILD/dist/"staffetta-*.whl "$STAFFETTA/dist/"
```

## Первая передача за пять минут

Учебный проект — временная копия `demo/sender-work` из репозитория Staffetta.

```bash
DEMO="$(mktemp -d)/demo проект"
cp -R "$STAFFETTA/demo/sender-work" "$DEMO"
staffetta pack \
  --goal "починить разбор CSV в импорте продаж; остановился на парсере" \
  --decision "чинить парсер, а не данные: CSV перезаписывается при каждом импорте" \
  --next "проверить парсер на машине получателя и продолжить импорт" \
  --root "$DEMO" \
  --file "$DEMO/src/parse_csv.py" \
  --file "$DEMO/tests/test_parse_csv.py" \
  --file "$DEMO/data/sales_local.csv" \
  --attach "$DEMO/src/parse_csv.py" \
  --out "$DEMO/передача задачи"
staffetta brief "$DEMO/передача задачи" \
  --ask "Какие два случая стоит добавить в тест разбора CSV?" \
  --excerpt "src/parse_csv.py:7-14"
```

`brief` напечатает записку с вопросом и строками 7–14 парсера — вставьте её
в чат без доступа к диску целиком. Проверка на отдельной копии получателя:

```bash
RECIPIENT="$(mktemp -d)/копия получателя"
cp -R "$STAFFETTA/demo/recipient-work" "$RECIPIENT"
staffetta check "$DEMO/передача задачи" "$RECIPIENT"
```

Ожидаемый вывод: `src/parse_csv.py  совпадает`, `tests/test_parse_csv.py  изменён`,
`data/sales_local.csv  отсутствует`, итог — код 1 (это нормальный результат
проверки, а не сбой).

## Маршрут для реальной задачи

Перейдите в папку своего рабочего проекта и сохраните её путь:

```bash
PROJECT="$(pwd -P)"
```

### 1. Выбрать файлы и собрать передачу

`--file` кладёт в манифест только SHA-256; `--attach` добавляет байты внутрь
передачи — они нужны для `brief` и для восстановления у получателя.

```bash
staffetta pack \
  --goal "починить разбор CSV в импорте продаж; остановился на парсере" \
  --decision "чинить парсер, а не данные: CSV перезаписывается при каждом импорте" \
  --next "проверить парсер на машине получателя и продолжить импорт" \
  --rejected "править CSV вручную: правка теряется при перезаписи" \
  --root "$PROJECT" \
  --file "$PROJECT/src/parse_csv.py" \
  --file "$PROJECT/tests/test_parse_csv.py" \
  --attach "$PROJECT/src/parse_csv.py" \
  --out "$PROJECT/передача задачи"
```

### 2. Получить текст для внешнего чата (Grok и другие)

Записка — готовый текст: цель, решение, что проверил отправитель, ваш вопрос
и ровно те строки кода, что вы перечислили. Чат не имеет доступа к диску, поэтому
вставляйте текст целиком.

```bash
staffetta brief \
  "$PROJECT/передача задачи" \
  --ask "Какие два случая стоит добавить в тест разбора CSV?" \
  --excerpt "src/parse_csv.py:7-14" \
  > "$PROJECT/вопрос-чату.md"
```

Диапазон строк указывайте по текущему файлу (нумерация с 1). Если команда
завершилась ошибкой, `stdout` останется пустым — причина будет в `stderr`.

### 3. Вернуть ответ исходному агенту для проверки

Сохраните ответ чата в файл `$PROJECT/ответ-чата.md`, затем скажите исполнителю
(готовая фраза, дополните только деталями задачи):

> Вот ответ внешнего чата на вопрос из записки Staffetta: файл «ответ-чата.md»
> в папке проекта. Прочитай его, каждое утверждение проверь по исходникам
> проекта и по передаче «передача задачи», примени к коду только то, что
> подтвердилось, отчитайся, что именно изменено, и пересобери передачу командой
> `pack --force`, если файлы менялись.

### Проверка и восстановление (когда копия получателя на другой машине)

```bash
staffetta check "$PROJECT/передача задачи" "$PROJECT"
staffetta restore-missing "$PROJECT/передача задачи" "$PROJECT"
```

Ожидаемые локальные расхождения: статус `изменён` — наблюдаемый факт о рабочей
копии, из него не видно, что именно правилось. Отправитель описывает ожидаемую
правку в `--unknown`, а решение «ограничивается ли разница этой правкой»
принимает получатель. Пример: отправитель указал
`--unknown "В tests/test_parse_csv.py ожидается добавленный локальный
комментарий. Не проверено, ограничивается ли разница этим комментарием"`,
у получателя:

```text
tests/test_parse_csv.py  изменён
```

и код 1 — даже для описанной заранее правки. Если доступна исходная версия
отправителя, получатель сравнивает их сам; если доступен только SHA-256,
корректный вывод: «Файл изменён; соответствует ли изменение ожидаемому
комментарию, пока неизвестно».

На томах без жёстких ссылок (например, exFAT) `restore-missing` по умолчанию
откажется и напечатает точную команду повтора с флагом `--allow-nonatomic`;
добавляйте его только по своему решению, не по инициативе агента.

Staffetta работает локально, только читает файлы и ничего не отправляет по сети.
